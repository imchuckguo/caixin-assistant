# 采芯助手团队协作 Implementation Plan

> **For agentic workers:** Implement task by task with available tools once implementation is requested and all applicable approvals are satisfied. Use an available execution skill when helpful; otherwise execute directly. Track progress with checkbox (`- [x]`) syntax.

**Goal:** 提供可运行、可部署、加密共享的团队后端及扩展客户端。

**Architecture:** 独立 Node HTTP + SQLite 服务，成员令牌摘要认证、单次邀请和团队范围校验；扩展持有 AES-GCM 密钥、维护离线上传队列与修订号。云连接须用户精确来源授权，默认关闭。

**Tech Stack:** Node.js 24.14+ 内置 HTTP/crypto/sqlite/test、Web Crypto、Docker。

**Spec:** ../specs/2026-11-20-caixin-team-design.md

## Global Constraints

- 生产连接必须为 HTTPS；仅本地开发允许 localhost/127.0.0.1 的 HTTP 地址。
- 角色为 owner 和 member。
- 邀请单次有效，默认 24 小时到期，可由 owner 撤销。
- 成员令牌使用加密安全随机数生成，服务器仅存其摘要。
- 扩展不预置作者服务器。
- 不创建云资源；先交付可自行部署版本。

### Task 1: 加密与协议

**Files:** extension/lib/team-crypto.js、server/store.mjs、server/app.mjs、server/index.mjs。
**Interfaces:** `CaixinCrypto.key()` 返回随机 32 字节 base64url；`seal(key,teamId,recordId,value)`/`open(...)` 使用版本/teamId/recordId AAD。`createApp({dbPath,createToken,allowedOrigins,rateLimit})` 返回 HTTP server 和 close；所有接口前缀 /v1。

- [x] 实现 GET /v1/health、POST /v1/teams（部署创建令牌）、POST /v1/join（单次邀请）。
- [x] 成员 Bearer 鉴权后提供 GET /v1/team、POST/GET/DELETE /v1/invites、DELETE /v1/members/:id、POST /v1/leave。
- [x] 实现 POST /v1/records 批量乐观修订写入（每条本人所有），GET /v1/records?cursor= 增量读取，deleted 墓碑撤回。
- [x] SQL 事务保证邀请单次使用和递增修订，限制请求体/记录/批次/页大小、速率和 Origin。
- [x] 测试两团队隔离、角色权限、撤销令牌、邀请重用/到期/撤销、冲突、重启持久化与过大输入。
